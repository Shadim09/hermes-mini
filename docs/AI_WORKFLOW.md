# کار با هوش مصنوعی در این پروژه (هارنس، Skill، MCP)

سرپرست خواسته کل پروژه با ابزارهای هوش مصنوعی ساخته شود و تو بفهمی چه می‌شود. این سند دو چیز می‌گوید:
۱) این نسخه دقیقاً چگونه ساخته شد (صادقانه)، ۲) چطور خودت در ترمینال همین کار را تکرار و ادامه بدهی.

## ۱. این نسخه چگونه ساخته شد

| مرحله | ابزار | چه شد |
|---|---|---|
| خواندن صورت پروژه | هارنس چت Claude با ابزار فایل | PDF خوانده شد و نیازمندی‌های R1–R8 و فازها استخراج شد |
| تحقیق محدودیت‌ها | **MCP مستندات Cloudflare** | سقف‌های پلن رایگان Workers، D1، Workers AI، Cron و موضوع Access روی workers.dev از مستندات رسمی خوانده شد |
| نوشتن کد | ابزارهای فایل و Bash | `src/index.js`، migration، `wrangler.toml`، تست‌ها |
| تست | Bash + Node | تست واحد (۹ مورد) و تست سرتاسری (۲۰ مورد) با mock تلگرام/LLM و هاست Node |
| مستندات | همان | README، راهنما، معماری، گزارش |

**محدودیت‌های صادقانه:**
- در محیطی که این نسخه ساخته شد، دسترسی به رجیستری npm مسدود بود، پس `wrangler` نصب و اجرا نشد؛ **deploy واقعی و تست با Workers AI و تلگرام واقعی انجام نشده** و کار توست (GUIDE بخش‌های ۴ تا ۸).
- تست سرتاسری با «مغز» تقلبیِ قاعده‌محور انجام شد، نه مدل زبانی واقعی؛ کیفیت فهم فارسی را فقط روی ربات واقعی می‌توانی بسنجی.
- دیتابیس تست SQLite درون‌حافظه بود، نه D1 واقعی (رفتار SQL یکسان است ولی نه محدودیت‌ها و تأخیر).

## ۲. سه مفهوم، به زبان ساده

**هارنس (Harness).** یک مدل زبانی تنها فقط متن می‌نویسد. هارنس آن را به «دست و چشم» وصل می‌کند: خواندن/نوشتن فایل، اجرای دستور، جست‌وجو، و حلقهٔ «کار کن ← نتیجه را ببین ← اصلاح کن». Claude Code نمونهٔ ترمینالی است.

**Skill.** یک پوشه با فایل `SKILL.md`: دستورالعمل تخصصی برای یک نوع کار. هوش مصنوعی وقتی کار مرتبط پیش بیاید آن را می‌خواند و طبقش عمل می‌کند. نمونه در پروژه: `.claude/skills/hermes-deploy/SKILL.md` (چک‌لیست deploy امن).

**MCP (Model Context Protocol).** استانداردی برای اتصال هوش مصنوعی به سرویس‌های بیرونی با «ابزار»هایی که سرویس تعریف می‌کند. با MCP کلادفلر، هوش مصنوعی می‌تواند مستندات را جست‌وجو کند و (با مجوز تو) منابع حساب را ببیند یا بسازد.

**فایل `CLAUDE.md`.** حافظهٔ پروژه برای هارنس: قواعد سخت (مثلاً «هیچ secret ای در ریپو»). هر بار که Claude Code در این پوشه باز شود، آن را می‌خواند.

## ۳. تکرار و ادامهٔ کار با Claude Code 🧑

> دستورهای نصب و نام ابزارها ممکن است با گذشت زمان عوض شوند؛ اگر دستوری کار نکرد، مستندات رسمی Claude Code را ببین.

۱) نصب و ورود (مطابق مستندات رسمی Claude Code)، سپس در پوشهٔ پروژه:

```bash
cd hermes-mini
claude
```

۲) اتصال MCP کلادفلر (برای مستندات و منابع حساب؛ اولین بار مرورگر برای مجوز باز می‌شود):

```bash
claude mcp add --transport http cloudflare https://mcp.cloudflare.com/mcp
```

(آدرس بالا همان است که مستندات سرور قدیمی‌تر کلادفلر به‌عنوان جایگزین معرفی می‌کند؛ اگر کار نکرد، آدرس فعلی را از مستندات Cloudflare بگیر.)

۳) پرامپت‌های نمونه، به ترتیب (هر کدام را اجرا کن، **نتیجه را بخوان** و بپرس چرا):

```text
CLAUDE.md و src/index.js را بخوان و بگو هر تابع چه می‌کند. هنوز چیزی را تغییر نده.
```
```text
npm test و سناریوی e2e را اجرا کن و اگر چیزی شکست بخورد علتش را توضیح بده.
```
```text
یک قابلیت اضافه کن: دستور «کار X را تا فردا عقب بینداز». اول طراحی را در چند خط بگو، بعد migration جدید (نه ویرایش قدیمی)، کد و تست.
```
```text
از skill hermes-deploy استفاده کن و برای deploy چک‌لیست را قدم‌به‌قدم با من پیش ببر. هر جا secret لازم شد، فقط دستور wrangler را بده و مقدار را از من نخواه.
```

۴) قواعد کار امن با هوش مصنوعی:
- توکن‌ها را هیچ‌وقت در چت یا فایل نگذار.
- قبل از پذیرفتن تغییر، diff را بخوان (`git diff`).
- بعد از هر تغییر `npm test` و `bash scripts/check-secrets.sh`.
- تغییر دیتابیس فقط با migration **جدید**.
- اگر هوش مصنوعی چیزی گفت که نمی‌فهمی: «ساده‌تر توضیح بده» و «کجای کد این را نشان می‌دهد؟»

## ۳.۵ مثال: اضافه‌کردن سه فیچر (Undo، یادآور، ویس)

همین چرخه برای فیچرهای دوم تکرار شد: ۱) مستندات Whisper و قیمت نیورون با MCP کلادفلر خوانده شد (نه حدس از حافظه)؛ ۲) migration جدید `0002` نوشته شد (فایل قبلی دست نخورد)؛ ۳) هر فیچر تست واحد و سناریوی e2e گرفت (۲۲ تست واحد، ۳۸ بررسی سرتاسری)؛ ۴) قواعد تازه به `CLAUDE.md` اضافه شد؛ ۵) deploy و تست روی ربات واقعی با خود کاربر. محدودیت صادقانه: مدل زبانیِ تست محلی تقلبی است و فهمیدن واقعی «فردا ساعت ۹» فقط روی ربات واقعی دیده می‌شود.

## ۴. در دفاع چه بگویم؟

سه جملهٔ صادقانه که برای دفاع مفید است:

1. «پروژه را با هوش مصنوعی ساختم، همان‌طور که درس خواسته بود؛ سند AI_WORKFLOW توضیح می‌دهد کدام بخش‌ها چطور ساخته و تست شد.»
2. «می‌توانم جریان یک پیام را از webhook تا پاسخ توضیح بدهم، و توضیح بدهم هر لایهٔ امنیتی چه حمله‌ای را مهار می‌کند.»
3. «این‌ها را خودم روی حساب واقعی deploy و تست کردم و این مشکل‌ها را دیدم: …» (در گزارش فاز ۶ مشکلات واقعی خودت را بنویس.)
