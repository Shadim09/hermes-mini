# دردسرهای رایج: علامت ← تشخیص ← راه‌حل

صورت پروژه فقط علامت را می‌دهد. اینجا راه تشخیص و اقدام را می‌بینی.
قبل از هر چیز این دو دستور را بزن؛ نصف مشکلات را نشان می‌دهند:

```bash
bash scripts/webhook-info.sh        # تلگرام چه می‌گوید؟ (last_error_message، pending_update_count)
npm run logs                        # Worker چه می‌بیند؟
```

---

## ۱. ربات کاملاً ساکت است و در لاگ هیچ درخواستی نیست

**یعنی:** مشکل **قبل** از Worker است؛ درخواست به کد ما نمی‌رسد.

**مظنون اصلی (مرتبط با Zero Trust):** **Cloudflare Access روی `workers.dev` یا روی کل Workerهای حساب فعال شده.**
Access قبل از اجرای Worker از بازدیدکننده لاگین می‌خواهد؛ تلگرام لاگین ندارد، پس درخواستش به صفحهٔ ورود/۴۰۳ می‌خورد.
(مستندات: Access را می‌توان برای یک Worker، برای همهٔ Workerها، یا برای یک hostname روشن کرد.)

**تشخیص:**
- `bash scripts/webhook-info.sh` ← `last_error_message` چیزی مثل ۴۰۱/۴۰۳/۳۰۲ نشان می‌دهد.
- `curl -i https://<worker>.workers.dev/health` به‌جای JSON، ریدایرکت یا صفحهٔ Access می‌دهد.

**راه‌حل:** داشبورد ← Workers & Pages ← Worker ← **Settings ← Domains & Routes** ← کنار `workers.dev` اگر «Cloudflare Access» روشن است، آن را خاموش کن
(برای Previews هم همین‌طور)؛ و در Zero Trust ← Access ← Applications بررسی کن سیاستی روی «همهٔ Workerها» نباشد.

**دلایل دیگر:** webhook ثبت نشده (`url` خالی در webhook-info)؛ secret در `set-webhook.sh` با `wrangler secret` یکی نیست (در این حالت لاگ یک ۴۰۳ نشان می‌دهد، که یعنی درخواست رسیده ولی رد شده)؛ توکن اشتباه.

---

## ۲. مرورگر خودم آدرس را باز نمی‌کند ولی ربات جواب می‌دهد

**طبیعی است.** `workers.dev` از داخل ایران فیلتر است (تلگرام هم؛ با VPN کار می‌کند). فیلتر روی اتصال **تو** است، نه روی سرورهای کلادفلر که با تلگرام صحبت می‌کنند.

**راه تست:** با `curl` یا اسکریپت (و VPN):

```bash
curl -sS https://<worker>.workers.dev/health
```

اگر با اسکریپت‌ها خطای `1010` یا مسدودشدن گرفتی: درخواست‌های `workers.dev` با User-Agent پیش‌فرض بعضی کتابخانه‌ها (مثل Python `urllib`) رد می‌شوند؛ یک User-Agent توصیفی بفرست
(`curl` پیش‌فرض معمولاً مشکلی ندارد؛ `dev/e2e.mjs` هم خودش یکی می‌فرستد).

---

## ۳. خطای deploy با کد `10405`

من این کد را عیناً در مستندات پیدا نکردم، پس حدس را حدس می‌نامم. صورت پروژه می‌گوید «پیش‌نیاز دامنه هنوز ساخته نشده».
محتمل‌ترین علت: **زیر‌دامنهٔ `workers.dev` حساب هنوز ثبت نشده.**

**راه‌حل:** داشبورد ← Workers & Pages ← «Your subdomain» ← یک نام انتخاب و ثبت کن؛ دوباره `npx wrangler deploy`.
(بعد از اولین deploy ممکن است یکی دو دقیقه خطای ۵۲۳ ببینی؛ مستندات می‌گوید خودش حل می‌شود.)

اگر بعد از ثبت زیر‌دامنه هم بود: **متن کامل خطا** را برای من بفرست (بدون توکن)، با همان دستوری که زدی.

---

## ۴. تلگرام یک پیام را چند بار می‌فرستد

**علت:** تلگرام تا وقتی پاسخ ۲xx نگیرد، همان update را دوباره می‌فرستد. اگر Worker خطا (۵xx) بدهد یا دیر جواب بدهد، تکرار می‌شود.

**در این پروژه:**
- بعد از تأیید secret همیشه ۲۰۰ فوری می‌دهیم.
- `processed_updates` تکراری‌ها را حذف می‌کند.

**تشخیص:** در لاگ `duplicate_update` را ببین. اگر تکرار مدام می‌آید، `webhook-info.sh` را بزن: `last_error_message` علت را می‌گوید.
اگر وسط کار کد را عوض کردی و Worker ۵۰۰ می‌داد، با `drop_pending_updates=true` (که `set-webhook.sh` می‌فرستد) صف قدیمی پاک می‌شود.

---

## ۵. بعد از آپدیت، ربات می‌گوید «یه مشکل داخلی پیش اومد»

**علت رایج:** کد جدید را deploy کردی ولی migration `0002` را روی D1 واقعی اجرا نکردی؛ کد ستون‌های `due_day` و … را می‌خواهد و وجود ندارند. لاگ: `no such column: due_day`.
**راه‌حل:** `npm run db:migrate:remote` و دوباره امتحان. ترتیب درست همیشه: migration، بعد deploy.

## ۶. ویس جواب نمی‌دهد یا «نتونستم پیام صوتی رو بشنوم»

در `npm run logs` یا Observability دنبال `voice_getfile_failed`، `voice_download_failed`، `voice_error` یا `stt_empty_output` بگرد. ویس بلندتر از ۶۰ ثانیه عمداً رد می‌شود. اگر سهمیهٔ روزانهٔ Workers AI تمام شده باشد، ویس و متن هر دو تا نیمه‌شب UTC خطا می‌دهند.

## ۷. خطاهای دیگری که ممکن است ببینی

| علامت | علت محتمل | اقدام |
|---|---|---|
| ربات می‌گوید «الان نمی‌تونم پیامت رو پردازش کنم» و در لاگ `llm_error` | سقف روزانهٔ ۱۰٬۰۰۰ نیورون Workers AI یا مدل روی پلن رایگان بسته | مدل دیگر یا OpenRouter (GUIDE بخش ۹.۳)؛ داشبورد ← Workers AI ← مصرف |
| `llm_invalid_output` زیاد | مدل ضعیف یا پرامپت | مدل بزرگ‌تر؛ نمونهٔ `sample` لاگ را بررسی کن |
| «متوجه منظورت نشدم» مدام | بعد از دو تلاش خروجی نامعتبر بود | همان |
| `no such table: tasks` | migration اجرا نشده یا روی دیتابیس دیگر | `npm run db:migrate:remote`؛ `database_id` را بررسی کن |
| خطای D1 «exceeded free tier daily row …» | سقف روزانهٔ D1 | تا نیمه‌شب UTC صبر یا کاهش مصرف |
| `/health` → `db:false` | binding `DB` یا شناسهٔ دیتابیس اشتباه | `wrangler.toml` را بررسی و دوباره deploy |
| یادآور نمی‌آید | `REMINDER_HOUR` ≠ ساعت فعلی تهران؛ کارِ باز نیست؛ Cron ثبت نشده | داشبورد ← Worker ← Triggers ← Cron؛ لاگ `reminder_sent` |
| `wrangler` در اولین اجرا خطای احراز هویت | وارد نشده‌ای | `npx wrangler login` |
