# فیچرهای اضافه: Undo، یادآور با تاریخ، پیام صوتی

هر سه فیچر روی همان معماری قبلی سوار شده‌اند: همچنان **یک فایل** `src/index.js`، فقط Workers + D1 + Workers AI، پلن رایگان، و هیچ دستور اسلشی‌ای اضافه نشده (مدل زبانی تصمیم می‌گیرد).

## ۱. Undo (برگرداندن آخرین تغییر)

| بگو | نتیجه |
|---|---|
| `برگردون` / `اشتباه شد` / `پشیمون شدم` | آخرین تغییر برگردانده می‌شود |

- هر تغییر (اضافه، انجام، بازکردن، حذف، تنظیم یادآور) هم‌زمان در جدول `action_log` ثبت می‌شود (در **همان batch**، پس یا هر دو ثبت می‌شوند یا هیچ‌کدام).
- برای هر تغییر، وضعیتِ *قبل* از آن ردیف‌ها ذخیره می‌شود؛ undo همان را برمی‌گرداند. اضافه‌کردن با soft-delete برگردانده می‌شود.
- چندبار «برگردون» = قدم‌به‌قدم عقب‌تر رفتن.
- فقط تغییرهای **۲۴ ساعت اخیر** برگردانده می‌شوند (تا «برگردون» یک هفته بعد چیز قدیمی را بر نگرداند). فقط ۳۰ ورودی آخر نگه داشته می‌شود.
- اکشن جدید `undo` بدون آرگومان است؛ مدل فقط تشخیص می‌دهد کاربر برگشت می‌خواهد.

## ۲. یادآور با تاریخ

| بگو | نتیجه |
|---|---|
| `فردا ساعت ۹ به مادرم زنگ بزنم` | کار + یادآور فردا ۰۹:۰۰ |
| `بخر شیر جمعه` | یادآور جمعه، ساعت صبحگاهی (`REMINDER_HOUR`، پیش‌فرض ۸) |
| `یادآور شماره ۲ رو بذار ۲۵ آبان` | یادآور برای کار موجود |
| `یادآور شماره ۲ رو بردار` | حذف یادآور |

**چطور کار می‌کند**
1. مدل خودش تاریخ حساب نمی‌کند: در پرامپت یک **جدول تقویم ۳۰ روزه** (میلادی + روز هفته و تاریخ شمسی) می‌گذاریم و مدل فقط یکی را انتخاب می‌کند: `{"action":"add","items":[...],"due":{"date":"2026-11-03","hour":9}}`.
2. `parseAction()` شکل تاریخ/ساعت را اعتبارسنجی می‌کند (تاریخ واقعی، ساعت ۰ تا ۲۳)؛ `execute()` زمانِ گذشته را رد می‌کند (کار ذخیره می‌شود ولی بدون یادآور، با هشدار).
3. دیتابیس: `migrations/0002_features.sql` ستون‌های `due_day`، `due_hour`، `reminded_at` را اضافه می‌کند.
4. Cron هر ساعت (همان تریگر قبلی `30 * * * *`) کارهای باز را که زمانشان رسیده و `reminded_at` ندارند پیدا و پیام «⏰ یادآور» می‌فرستد؛ بعد از ارسال موفق `reminded_at` پر می‌شود (پس فقط یک‌بار). شرط «کوچک‌تر یا مساوی» است، پس اگر یک tick از دست رفت، tick بعدی جبران می‌کند. اگر ارسال به تلگرام شکست خورد، علامت نمی‌خورد و ساعت بعد دوباره تلاش می‌شود.
5. پیام صبحگاهیِ قبلی (لیست کارهای باز) سر جایش است.

محدودیت: دقت یادآور **ساعتی** است (چون cron هر ساعت اجرا می‌شود)، نه دقیقه‌ای.

## ۳. پیام صوتی

یک ویس بفرست، مثلاً «بخر شیر». ربات اول چیزی را که شنیده نشان می‌دهد و بعد عمل را انجام می‌دهد:

```
🎙 «بخر شیر»

✅ اضافه شد:
• بخر شیر
```

- مسیر: تلگرام `voice` → Worker با `getFile` آدرس فایل را می‌گیرد و دانلود می‌کند → **Whisper روی Workers AI** (`@cf/openai/whisper-large-v3-turbo`، زبان فارسی) → متن → همان مسیر معمولیِ مدل زبانی و اعتبارسنجی.
- متنِ شنیده‌شده همیشه نمایش داده می‌شود؛ اگر اشتباه شنیده شد، «برگردون» بگو (Undo و ویس مکمل هم‌اند).
- ویس بلندتر از **۶۰ ثانیه** یا بزرگ‌تر از ~۱٫۵ مگابایت رد می‌شود.
- هزینه: طبق مستندات Cloudflare حدود **۴۶٫۶۳ نورون در هر دقیقهٔ صدا** است؛ سهمیهٔ رایگان ۱۰٬۰۰۰ نورون در روز است، پس ویس‌های کوتاه عملاً تمام‌نشدنی‌اند (ولی همین سهمیه با مدل زبانی مشترک است).
- مدل را با متغیر `STT_MODEL` در `wrangler.toml` می‌شود عوض کرد.
- توکن ربات داخل آدرس دانلود فایل است؛ این آدرس هیچ‌جا لاگ نمی‌شود.

## تست سرتاسری محلی
`npm test` (۲۲ تست واحد) و `npm run mock` + `npm run host` + `npm run e2e` (۳۸ بررسی، شامل Undo، یادآور cron با زمان شبیه‌سازی‌شده و ویس با Whisper تقلبی). نکته: مدل زبانی در تست محلی تقلبی (rule-based) است؛ فهمیدنِ واقعیِ «فردا ساعت ۹» توسط Gemma فقط روی ربات واقعی قابل بررسی است.
