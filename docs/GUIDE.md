# راهنمای کامل و قدم‌به‌قدم

این راهنما برای کسی نوشته شده که تازه با ابزارهای هوش مصنوعی و Cloudflare کار می‌کند.
هر قدم مشخص می‌کند **چه کسی** باید انجامش بدهد:

- 🤖 = هوش مصنوعی (Claude) این کار را قبلاً انجام داده؛ تو فقط باید بفهمی چه شده.
- 🧑 = فقط **خودت** می‌توانی انجامش بدهی (حساب‌ها، توکن‌ها، ورود به حساب، تأیید).

> قانون طلایی: هیچ توکن یا کلیدی را در چت با هوش مصنوعی، در کد، یا در ریپو نچسبان.
> توکن‌ها فقط در ترمینال خودت و فقط با `wrangler secret put` وارد می‌شوند.

## ۰. هوش مصنوعی در این پروژه چه نقشی دارد؟

سرپرست درس خواسته پروژه با ابزارهای هوش مصنوعی ساخته شود، ولی تو باید **بفهمی** و در دمو **از آن دفاع کنی**. سه کلمه را بشناس:

| واژه | یعنی چه | در این پروژه |
|---|---|---|
| **هارنس (Harness)** | برنامه‌ای که مدل زبانی را به فایل‌ها، ترمینال و ابزارها وصل می‌کند تا فقط حرف نزند، کار هم بکند | Claude Code (ترمینال) یا همین محیط چت با ابزار فایل |
| **Skill** | پوشهٔ دستورالعمل که هوش مصنوعی برای کاری خاص می‌خواند | `.claude/skills/hermes-deploy/SKILL.md` — چک‌لیست deploy |
| **MCP** | استاندارد وصل‌کردن هوش مصنوعی به سرویس‌های بیرونی (مثلاً مستندات یا حساب Cloudflare) | سرور MCP کلادفلر برای جست‌وجوی مستندات و منابع |

## ۲. گرفتن کد و گذاشتن در گیت‌هاب 🧑

۱) فایل zip پروژه را باز کن و وارد پوشه شو:

```bash
cd hermes-mini
```

۲) در [github.com/new](https://github.com/new) با حساب `shadim09` یک ریپوی **خالی** به نام `hermes-mini` بساز
(بدون README و بدون `.gitignore`، چون در پروژه هست).

> ریپوی `amirabroun/hermes-mini` که در صورت پروژه آمده، مرجع/نمونه است و مال تو نیست؛ روی ریپوی خودت کار کن.

۳) اول امنیت، بعد commit:

```bash
git init -b main
git config user.name "نام خودت"
git config user.email "shadim1308@gmail.com"

bash scripts/check-secrets.sh      # باید بنویسد: no obvious secrets found
git add .
git status                         # دقت کن: .dev.vars و node_modules نباید در لیست باشند
git commit -m "feat: hermes-mini serverless Telegram task bot"
```

۴) push:

```bash
git remote add origin https://github.com/shadim09/hermes-mini.git
git push -u origin main
```

گیت‌هاب رمز عبور معمولی نمی‌پذیرد. یکی از دو راه:
- نصب GitHub CLI و `gh auth login` (ساده‌تر)
- ساخت Personal Access Token در GitHub → Settings → Developer settings، و استفاده از آن به‌جای رمز. (این توکن را هم هیچ‌جا در ریپو نگذار.)

<a id="3"></a>
## ۳. نصب و تست محلی

```bash
npm install            # 🧑 نصب wrangler
npm test               # تست‌های واحد: باید ۹ مورد پاس شود
```

تست سرتاسری بدون هیچ حساب و کلیدی (سه ترمینال، یا با `&`):

```bash
npm run mock           # تلگرام و مدل زبانی تقلبی روی پورت ۸۷۹۰
npm run host           # همین کد Worker روی Node، با دیتابیس موقت، پورت ۸۷۸۷
npm run e2e            # ۲۰ سناریو؛ همه باید PASS باشند
```

**این تست چه چیزی را ثابت می‌کند؟** secret، لیست سفید، افزودن/انجام/حذف، شماره نامعتبر، پیام تکراری، خروجی خراب LLM، یادآور.
**چه چیزی را ثابت نمی‌کند؟** رفتار واقعی مدل زبانی و محیط واقعی Cloudflare. آن‌ها را در بخش ۸ روی ربات واقعی می‌بینی.

<a id="4"></a>
## ۴. Cloudflare: ورود، دیتابیس، migration 🧑

۱) ورود به حساب (مرورگر باز می‌شود و اجازه می‌خواهد):

```bash
npx wrangler login
npx wrangler whoami
```

۲) **یک‌بار** زیر‌دامنهٔ workers.dev حسابت را بساز: داشبورد → Workers & Pages → بالای صفحه «Your subdomain».
(نبودنش یکی از دلایل شکست اولین deploy است؛ [`PITFALLS.md`](PITFALLS.md))

۳) ساخت دیتابیس D1:

```bash
npm run db:create
```

خروجی یک `database_id` می‌دهد. آن را در `wrangler.toml` به‌جای `PUT-YOUR-D1-DATABASE-ID-HERE` بگذار.
(شناسهٔ دیتابیس secret نیست و commit کردنش مشکلی ندارد.)

۴) اجرای migration روی دیتابیس واقعی:

```bash
npm run db:migrate:remote
```

با `y` تأیید کن. سه جدول ساخته می‌شود: `tasks`، `messages`، `processed_updates`.

<a id="5"></a>
## ۵. ساخت ربات تلگرام و گرفتن آیدی خودت 🧑

۱) در تلگرام با **@BotFather** گفتگو کن: `/newbot` ← نام ← یوزرنیم (باید به `bot` ختم شود).
توکنی شبیه `123456789:AAH...` می‌دهد. **این توکن را جایی جز مرحلهٔ ۶ وارد نکن.**

۲) آیدی عددی خودت را لازم داری (برای لیست سفید). راه ساده: به ربات **@userinfobot** پیام بده؛ عددی مثل `123456789` می‌دهد.

> این آیدی هویت توست و در secret store ذخیره می‌شود، نه در کد.

<a id="6"></a>
## ۶. Deploy و ثبت secretها 🧑

۱) اول deploy (هنوز secret نداریم، پس webhook با ۴۰۳ جواب می‌دهد؛ طبیعی است):

```bash
npx wrangler deploy
```

آخر خروجی آدرس Worker را می‌دهد: `https://hermes-mini.<subdomain>.workers.dev` ← این **آدرس زنده** برای تحویل است.

۲) secretها. هر دستور مقدار را در ترمینال از تو می‌پرسد (چیزی روی صفحه نمایش داده نمی‌شود):

```bash
openssl rand -hex 32               # یک رشتهٔ تصادفی بلند برای WEBHOOK_SECRET بساز و کپی کن

npx wrangler secret put WEBHOOK_SECRET     # همان رشتهٔ تصادفی
npx wrangler secret put BOT_TOKEN          # توکن BotFather
npx wrangler secret put ALLOWED_USER_ID    # آیدی عددی خودت
```

(در ویندوز اگر `openssl` نبود: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`)

۳) بررسی سلامت (با **curl**، نه مرورگر؛ مرورگرِ داخل ایران `workers.dev` را باز نمی‌کند):

```bash
curl -sS https://hermes-mini.<subdomain>.workers.dev/health
# {"ok":true,"service":"hermes-mini","tehran_today":"2026-..","db":true}
```

و آزمایش امنیت: بدون هدر secret باید ۴۰۳ بگیری:

```bash
curl -i -X POST https://hermes-mini.<subdomain>.workers.dev/webhook -d '{}'
# HTTP/2 403
```

<a id="7"></a>
## ۷. وصل‌کردن webhook 🧑

در همان ترمینال (مقادیر فقط در همین نشست ترمینال می‌مانند):

```bash
export BOT_TOKEN='توکن BotFather'
export WEBHOOK_SECRET='همان رشتهٔ تصادفی مرحلهٔ ۶'
export WORKER_URL='https://hermes-mini.<subdomain>.workers.dev'

bash scripts/set-webhook.sh        # باید {"ok":true,...} بدهد
bash scripts/webhook-info.sh       # url درست؛ last_error_message نباید وجود داشته باشد
```

> در تلگرام، `secret_token` همان چیزی است که تلگرام در هدر `X-Telegram-Bot-Api-Secret-Token` هر درخواست می‌فرستد. Worker فقط درخواست‌هایی را می‌پذیرد که این هدر را درست داشته باشند.

<a id="8"></a>
## ۸. تست روی ربات واقعی 🧑

با VPN روشن، در تلگرام به ربات خودت پیام بده و این سناریو را برو (همان چیزی است که در داوری امتحان می‌شود):

| پیام | انتظار |
|---|---|
| `سلام` | پاسخ دوستانه |
| `بخر شیر` | ✅ اضافه شد |
| `نون و پنیر هم بخر` | یک یا دو کار اضافه می‌شود |
| `چیه کارام؟` | لیست شماره‌دار |
| `شیر رو خریدم` | ✔️ انجام شد |
| `شماره ۹ رو حذف کن` | «شماره ۹ توی لیست نیست» (نه خطا، نه حذف) |
| `حذف شماره ۱` | 🗑 حذف شد |
| `همین رو حذف کن` | یا همان کار اخیر حذف می‌شود یا سؤال توضیحی می‌پرسد |
| `همه رو حذف کن` | همه حذف می‌شوند (نرم؛ در دیتابیس می‌ماند) |
| یک جملهٔ مبهم، مثل `اون یکی رو بزن` | سؤال توضیحی، بدون تغییر در لیست |

اگر کیفیت فهم مدل ضعیف بود، [بخش ۹.۳](#93) را ببین.

از **یک حساب دیگر** هم پیام بده: ربات نباید هیچ پاسخی بدهد (و در لاگ `unauthorized_sender` ثبت می‌شود).

<a id="9"></a>
## ۹. لاگ زنده، یادآور، مدل دیگر

### ۹.۱ لاگ زنده (برای دمو الزامی است)

```bash
npm run logs
```

هر پیام چند خط JSON لاگ می‌سازد؛ رویدادهای مهم: `unauthorized_sender`، `duplicate_update`، `llm_invalid_output`، `llm_error`، `reminder_sent`.
مشاهده‌پذیری (Observability) در `wrangler.toml` روشن است؛ در داشبورد: Worker ← Observability.

### ۹.۲ یادآور صبحگاهی (امتیاز اضافه)

Cron Trigger هر ساعت در دقیقهٔ ۳۰ (UTC) اجرا می‌شود. چون تهران UTC+۳:۳۰ است، این دقیقاً سر ساعت تهران است. کد فقط وقتی پیام می‌فرستد که ساعت تهران برابر `REMINDER_HOUR` باشد (پیش‌فرض ۸).

برای تست سریع: `REMINDER_HOUR` را در `wrangler.toml` روی ساعت **بعدیِ** تهران بگذار، `npx wrangler deploy` بزن، و تا سر ساعت صبر کن. بعد به مقدار دلخواه (مثلاً ۸) برگردان و دوباره deploy کن.
(پلن رایگان تا ۵ Cron Trigger در هر حساب اجازه می‌دهد؛ ما ۱ تا استفاده کرده‌ایم.)

### ۹.۳ اگر مدل Workers AI فارسی را خوب نفهمید  <a id="93"></a>

دو راه، بدون تغییر کد:

۱) مدل دیگری از [فهرست مدل‌های Workers AI](https://developers.cloudflare.com/workers-ai/models/) که روی پلن رایگان آزاد است را در `LLM_MODEL` بگذار.
   توجه: بعضی مدل‌ها (مثل `kimi-k2.6` و `glm-5.2`) روی پلن رایگان بسته‌اند و خطای ۴۰۳ می‌دهند. فهرست‌ها تغییر می‌کنند؛ پیش از استفاده بررسی کن.

۲) استفاده از OpenRouter یا هر سرویس سازگار با OpenAI:

```toml
# wrangler.toml → [vars]
LLM_PROVIDER = "openai-compatible"
LLM_BASE_URL = "https://openrouter.ai/api/v1"
LLM_MODEL    = "یک مدل رایگان از OpenRouter"
```

```bash
npx wrangler secret put LLM_API_KEY      # 🧑 کلید را فقط اینجا وارد کن
npx wrangler deploy
```

<a id="11"></a>
## ۱۱. اگر چیزی خراب شد

اول [`PITFALLS.md`](PITFALLS.md) را بخوان (چهار مشکل رایجِ صورت پروژه، با راه تشخیص).
اگر حل نشد: **خروجی دقیق خطا** (بدون توکن!) را برای هوش مصنوعی بفرست و بگو کدام دستور را زدی. بدون متن خطا، حدس زدن کمکی نمی‌کند.

اگر توکن اشتباهی جایی لو رفت (چت، ریپو، اسکرین‌شات):
۱) BotFather ← `/revoke` ← ربات را انتخاب کن ← توکن جدید بگیر.
۲) `npx wrangler secret put BOT_TOKEN` با توکن جدید.
۳) `bash scripts/set-webhook.sh` را دوباره اجرا کن.
۴) اگر در گیت رفته بود، فقط حذف فایل کافی نیست؛ توکن قدیمی باید باطل باشد (همان مرحلهٔ ۱).
